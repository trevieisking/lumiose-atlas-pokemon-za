## Preferred recovery process — copy, do not remove

1. The owner opens the original Workspace guide while signed in. Navigate to **Maps → relevant Wild Zone or sector → zoom/close-up** and identify one usable map view. Start with **Bleu Sector 3 / My Favorite Holovator #61**, near Bleu Plaza and Aymis Park: a physical Holovator gallery already exists in Edition B, making it a useful first alignment cross-check.
2. **First choice: original image file.** When a genuine separate map image is displayed, save/export its image file at full resolution and preserve its native bytes. If the close-up is only a CSS/browser crop of a bigger image, save that underlying image rather than mistaking the enlarged crop for a new high-resolution asset. Do not share an entire authenticated browser session or secrets.
3. **Fallback: game or browser screenshot** owned by the user, preferably direct Switch screenshot or digital capture rather than a camera photo of a display. Set map **north-up** where possible; show the entire useful map extent and at least three named, recognisable common landmarks. Capture a wide context view and a closer detail view, with sector/Wild Zone name visible. Avoid menus, icons or UI overlays covering the intended landmarks. Keep the full original screenshot unmodified; derive crops only as separate copies.
4. Record: source edition/page, original filename, image dimensions, upload date, visible labels, north orientation, zoom/perspective, three or more matched landmark descriptions, original pixel checksum, reuse/rights note, and any obscured areas. Redact personal UI/account data where necessary.
5. Cross-register to the existing **1920 × 1920** city frame by measuring matched landmark coordinates, *not* by matching a screenshot's screen pixel to an Atlas pixel. An unrotated crop needs scale/translation; rotated captures may need similarity/affine registration; photos with display perspective need a perspective correction first. Reserve independent landmarks to calculate reprojection residual. If matching is ambiguous or error is high, mark the region **unregistered** and seek a better capture. Record the transform, landmarks and error in a new evidence file; do not silently change the canonical basemap.
6. Once verified, render each close-up as an **optional, source-labelled layer** linked from the appropriate sector or Wild Zone. Keep the original city base, existing markers, search and saved completion untouched. Use the common coordinate transform so city/close-up pins do not drift on pan, rotation or mobile pinch. If an image proves only a building/neighbourhood, its labels remain *approximate*.
7. For ladders, scaffolding, lifts and roofs use separate evidence records for **street entrance**, **vertical transition**, **roof landing** and **onward traversal**. A photographed lift or yellow map symbol does not prove exact rooftop connectivity. Do not permanently pin moving Hyperspace DLC distortions.
8. Add maps one at a time on a new **implementation** branch/PR. Tests must check image dimensions/checksums, ≥3 anchored landmarks with a held-out geometric cross-check, correct geographic target, preservation of existing 48 sectors/20 Wild Zones/21 lift records and 111 photos, zero unexpected item or roof pins, correct gesture/compass behaviour, existing guide navigation, saved progress and feedback/Supabase isolation. Run real Chromium phone-sized/desktop checks and review screenshots before promoting. Do not treat simulated phone emulation as physical device testing.
