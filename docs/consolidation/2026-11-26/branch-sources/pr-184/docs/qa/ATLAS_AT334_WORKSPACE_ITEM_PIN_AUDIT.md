# AT-334 — Recover the actual old Workspace item pin data

25 November 2026. The owner recalled that the Workspace guide previously displayed large Poké Ball markers. Actual v37 and original v35 source ZIPs were recovered from the owner's Library, read-only. Their original `map-items.json` bytes match (SHA-256 e76661e901bccd5fdac3eba577003429223f82f54767f956da023da316723fee). Both contain 146 named points with original ID, zone, normalized city-image X/Y, icon and numerical height. The archived native city JPG has the same Git blob ID as our preserved original 1920px image. This establishes the original rendering coordinate space, not the physical accuracy of each pickup. The GitHub source contains 155 occurrences and 146 distinct IDs. Reconstructed canonical tuples, including the recovered height values, match the independently computed archive checksum. The original archive and code are not copied to the public repo; retain only the existing marker evidence in the structured research register.

## Candidate reconciliation

All 146 archived names match at least one nonreward/non-hidden-outcome candidate in the same zone. 111 have an exclusive single candidate, nine share a single candidate with another old pin, 24 have several candidates, two are Colorful Screw leads requiring separate canonical 100-Screw reconciliation. 152 distinct ledger candidates overall; no automatic collection-key join. 264 item records include gifts/rewards/hidden outcomes and do not represent 264 fixed pins. Old data is not an exhaustive item catalogue. Treat every candidate as unverified until route, scene, identity and physical point evidence agrees.

## Height and unique TM checks

The old app inferred rooftop when height exceeded 40 and underground/lower when negative. This conflicts with actual published locations. TM103 is on a roof but its archived value is -10.6, while TM027 is on the central island with value 76.5. Keep every original height as raw evidence with unknown units and datum, never infer actual floor from that threshold. All 18 archived TM identities have matching unique name/zone checklist candidates and independently researched destination descriptions (the primary [move guide](https://altissimo1.github.io/Supplementary-Series/Legends/Legends-Z-A/moves.html) plus other sources including [TM054 guide](https://pokemongohub.net/post/guide/all-tm-locations-in-pokemon-legends-z-a/)). See the register for per-record notes and limits. No pixel or physical floor validation claimed. Existing two Screw leads (8715 and 8808) both match only the single zone-list screw entry, so do not collapse them or assign canonical numbers.

## Source coordinate pilot

Two public Gamer Guides records (TM079 Hurricane, [source](https://www.gamerguides.com/pokemon-legends-z-a/database/items/tms-1/hurricane), XY 14609/6645; TM054 Draco Meteor, [source](https://www.gamerguides.com/pokemon-legends-z-a/database/items/tms-1/draco-meteor), XY 9668/9723) offer same-item comparison candidates. Other pages failed to expose a coordinate or were inaccessible. Do not fit a citywide transform from two approximate pairs. Source map layers and exact marker IDs remain unconfirmed; preserve old AT-332 references. Serebii is a strong original-data provenance lead because the archive uses its item icon references and the [Wild Zone 1 table](https://www.serebii.net/pokearth/lumiosecity/wildzone1.shtml) matches the original catalogue; its [interactive city map](https://www.serebii.net/pokearth/lumiosecity/) has item and Screw layers. Raw data download was unavailable, and the exact original extraction method remains unproven. No new third-party bulk import.
